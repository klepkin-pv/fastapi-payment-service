# Состояние проекта

Вызывается по запросу, а не постоянно. Результат — короткий дашборд, не простыня вывода.

## Порядок

### 1. Определить проект

```bash
cat package.json 2>/dev/null | head -20
cat pyproject.toml 2>/dev/null | head -20
cat go.mod 2>/dev/null | head -5
cat Cargo.toml 2>/dev/null | head -5
```

Инструменты берутся из скриптов проекта, а не придумываются. Есть `npm run lint` — запускается он.

### 2. Запустить что есть

| Что | Как |
|-----|-----|
| Тесты | `npm test`, `pytest`, `go test ./...`, `cargo test` |
| Линт | `npm run lint`, `ruff check .`, `golangci-lint run` |
| Типы | `npx tsc --noEmit`, `mypy .`, `go vet ./...` |
| Покрытие | `npm run test:coverage`, `pytest --cov` |
| Уязвимости | `npm audit --omit=dev`, `pip-audit` |

Чего нет в проекте — пропускается, а не доустанавливается.

### 3. Заметки по коду

```bash
grep -rn "TODO\|FIXME\|HACK\|XXX" --include='*.ts' --include='*.tsx' --include='*.js' --include='*.py' . \
  | grep -v node_modules | wc -l
```

### 4. Дашборд

```
Тесты       ✅ 42 проходят
Линт        ⚠️ 3 предупреждения
Типы        ✅ без ошибок
Покрытие    71%
Заметки     6 TODO, 1 FIXME
Зависимости 2 moderate
```

Отдельно — только то, что требует действия. Подробный вывод не пересказывать: он у пользователя перед глазами.

## Плохое состояние — не приговор

Если тесты падают или есть уязвимости, это факт для решения, а не задача. Чинить — по отдельной просьбе.
