# AI_LOG

## Инструменты и модели

- ZCode — агентная среда: основная сессия и роли-субагенты (`architect`, `implementer`, `critic`) на модели `deepseek/deepseek-v4.1-flash`.
- Текст ТЗ из PDF извлечён `pypdf` и передан субагентам как бриф.
- Проверка на машине: uv 0.13.1, Python 3.14.7, PostgreSQL 18.6, Docker 29.8 с Compose, pytest, ruff, pre-commit.

## Ключевые запросы к ассистенту

1. **Планирование.** В бриф для `architect` уложены весь текст ТЗ, жёсткие требования (SQLAlchemy + Alembic + PostgreSQL, uv, docker-файлы в `docker/`, только докстринги, коды ответов ровно по ТЗ) и список неоднозначностей вида «в ТЗ не сказано — предложи решение и альтернативу». Итог — план из 15 задач с критериями успеха по баллам ТЗ.
2. **Реализация API платежей.** Задание `implementer`: перечислить точные файлы, сигнатуры чистых функций, CHECK-констрейнты, требование «тесты раньше кода», запрет комментариев и таблицу «доменная ошибка → HTTP-код и тело» из ТЗ.
3. **Ревизия.** Задание `critic`: проверить деньги, идемпотентность и коды ответов против ТЗ, а не стиль.

## Ошибки модели и как они замечены

1. **Миграции ушли в SQLite вместо PostgreSQL.** Контейнер `migrations` не получал `DATABASE_URL`, а у настройки был молчаливый дефолт. Замечено по логу `Context impl SQLiteImpl` и падению api с `relation "tariffs" does not exist`. Исправлено: `DATABASE_URL` стал обязательным, переменная проброшена в контейнер миграций.
2. **Заглушка секрета внутри миграций.** Чтобы Alembic мог импортировать модели, агент подставлял фиктивный `WEBHOOK_SECRET` в `env.py` — обходной путь вместо причины. Убрано: секрет проверяется на старте приложения, а миграции берут URL из того же конфига, что и сервис.
3. **`created_at` в двух форматах.** При создании ответ отдавал UTC (`Z`), при повторном чтении из PostgreSQL — локальную зону (`+03:00`), потому что так возвращает timestamptz. Замечено сравнением двух ответов на один платёж. Исправлено настройкой соединения: все даты — UTC.
4. **Хрупкий формат тела вебхука.** `HTTPException(409)` вернул бы `{"detail": ...}` вместо требуемого ТЗ `{"error": "invalid_transition"}` — решение отклонено ещё на плане, тела собираются явно.
5. **Длина `Idempotency-Key`.** Ключ длиннее 255 символов проходил в тестах на SQLite, но на PostgreSQL давал `DataError` и 500. Нашёл отдельный ревью-агент сверкой поведения на живой базе (не только тестами). Исправлено ограничением заголовка, поведение закреплено тестом.

## Проверено

68 тестов зелёные (`uv run pytest`), миграции накатываются на PostgreSQL 18 и SQLite, `docker compose up` поднимает db + migrations + api, сценарии ТЗ проверены curl в контейнере и локально.
