# Decisions

_Архитектурные решения: чтобы не переоткрывать их в новых сессиях. Формат записи ниже, старые записи не правятся._

---

## 2026-10-14 — Синхронный SQLAlchemy 2.x + psycopg 3

**Почему:** минимальный код и простые тесты; конкурентность закрывается unique-констрейнтом на `idempotency_key`, а не async-сессией; проще объяснять на созвоне

**Альтернативы:** async SQLAlchemy + asyncpg — лишние асинхронные фикстуры без выигрыша для задачи

**Утвердил:** заказчик (требование «SQLAlchemy, Alembic, PostgreSQL»), выбор sync — агент

**Последствия:** эндпоинты — обычные `def`; `Session` через `Depends`; денежные CHECK-констрейнты в БД как второй барьер

---

## 2026-10-14 — Деньги только целым числом в копейках

**Почему:** требование ТЗ (19900 ₽ → 1990000, никаких float); целочисленная арифметика исключает потери в скидке и графике

**Альтернативы:** `Decimal`/`Numeric` — сложнее и в ТЗ запрещён float; в БД `int` + CHECK

**Утвердил:** заказчик (ТЗ)

**Последствия:** все денежные расчёты — `int`, `//`, `divmod`; тесты сравнивают суммы точно

---

## 2026-10-14 — График рассрочки не хранится в БД

**Почему:** `schedule` детерминированно выводится из `amount` и `installment_months`; одна копия правды вместо двух

**Альтернативы:** JSON-столбец — дублирование денежных данных и риск рассинхрона

**Утвердил:** агент

**Последствия:** в ответах `schedule` считается на лету (`null` для card/sbp)

---

## 2026-10-14 — Тесты на SQLite in-memory, прод и compose — PostgreSQL 18

**Почему:** тесты без внешних сервисов — воспроизводимы локально и в CI; ТЗ допускает SQLite; специфика заперта в `conftest.py`. PostgreSQL проверяется миграцией, контейнером `migrations` и локальным запуском

**Альтернативы:** тесты против PostgreSQL — требуют поднятой БД у каждого проверяющего и service-контейнера в CI

**Утвердил:** заказчик (требование PostgreSQL в проде), выбор тестовой БД — агент

**Последствия:** `created_at` на SQLite без tz-суффикса — формат в тестах не проверяется; расхождение записано в `WORKING-CONTEXT.md`

---

## 2026-10-14 — Контейнер миграций + миграции при локальном запуске

**Почему:** заказчик хочет видеть отдельный контейнер `migrations`, применяющий схему; api стартует после его успешного завершения (`service_completed_successfully`). Локальный запуск прогоняет те же миграции перед стартом сервера

**Альтернативы:** миграции в entrypoint api (смешивает ответственности); ручной `alembic upgrade` (ломает «запуск с первого раза»)

**Утвердил:** заказчик

**Последствия:** один образ для api и migrations, разные команды; `local.run.*` всегда прогоняет `alembic upgrade head`

---

## 2026-10-14 — Подпись вебхука всегда обязательна

**Почему:** бонусная часть ТЗ принята как обязательная по решению заказчика; режим «без подписи» не нужен, вариантов поведения не плодим

**Альтернативы:** проверка только при непустом `WEBHOOK_SECRET` — отклонено: два режима вместо одного

**Утвердил:** заказчик

**Последствия:** `WEBHOOK_SECRET` обязателен при старте; все запросы к `/webhooks/bank` без корректного `X-Signature` → 401; тесты и curl-примеры подписывают тело

## 2026-10-14 — Python 3.14 локально и в образе

**Почему:** требование заказчика, на машине Python 3.14.7; ТЗ «3.11+» выполнено

**Альтернативы:** 3.12 как более консервативный — отклонено заказчиком

**Утвердил:** заказчик

**Последствия:** образ `python:3.14-slim`; `requires-python = ">=3.11"` сохраняется; риски колёс под 3.14 проверены на задаче 2

## 2026-10-14 — Compose — `docker/docker-compose.prod.yml`, всё docker-содержимое в `docker/`

**Почему:** заказчик просил изолировать docker-файлы и скрипты в `docker/`; раскладка проекта того же требует. README даёт обе команды: локально и контейнер

**Альтернативы:** compose в корне ради буквального `docker compose up` из бонуса ТЗ — отклонено заказчиком (выбран явный `-f`)

**Утвердил:** заказчик

**Последствия:** команда — `docker compose -f docker/docker-compose.prod.yml up --build`; порты БД не публикуются (5432 занят локальным PostgreSQL)

## 2026-10-14 — Фронтенд не делаем, остальные бонусы ТЗ берём

**Почему:** ТЗ прямо говорит «фронтенд не нужен»; заказчик подтвердил. Остальные бонусы (docker, Alembic, подпись, фильтры `GET /payments`, CI, правила ассистента) дешёвы и повышают оценку

**Альтернативы:** демо-страница `demo.html` + `demo.js` — снята по решению заказчика

**Утвердил:** заказчик

**Последствия:** `frontend/` не создаётся, никакого JS в сервисе

## 2026-10-14 — Промокод называется STUDY10

**Почему:** репозиторий публикуется как самостоятельный проект, следов заказчика в нём быть не должно; кодовое слово промокода заменено на нейтральное, механика не изменилась (−10 %, регистр не важен)

**Альтернативы:** оставить исходное название — отклонено: оно попадало в README, тесты и примеры curl

**Утвердил:** заказчик

**Последствия:** в коде, тестах и примерах используется STUDY10; сценарий «промокод в другом регистре» сохранён

## 2026-10-14 — `.zcode` фильтруется для сдачи, правила ассистента — бонус ТЗ

**Почему:** «Свои правила для ассистента в репозитории» — бонус ТЗ; заказчик просил оставить роли, скиллы и правила, которые реально пригодились, лишнее (figma, неиспользуемые инструменты) убрать

**Альтернативы:** выложить `.zcode` целиком — шум; выложить только `AGENTS.md` — теряются определения ролей

**Утвердил:** заказчик

**Последствия:** `AGENTS.md` приводится в соответствие с оставшимися файлами; служебное (`.zcode/state/`, `.zcode/config.json`) в `.gitignore`

## 2026-10-14 — `payment.id` — int, email — `EmailStr`

**Почему:** с UUID запрос `/payments/999` даёт 422 и ломает тест ТЗ «несуществующий платёж → 404»; `EmailStr` отклоняет мусор стандартным 422 из ТЗ

**Альтернативы:** UUID4; свободная строка email

**Утвердил:** заказчик

**Последствия:** пути — числовые id; email валидируется на границе до бизнес-логики
